# Pi CPU cooling on Ender FAN1

FAN1 is physically identified as the Pi cooler. FAN2 is air assist. Automatic
cooling is opt-in with E3_CPU_COOLING=1 in the hardware-node service environment.
It uses full FAN1 power at or above 45 C, switches off at or below 40 C, and
retains the previous demand between these temperatures. The worker polls every
five seconds. A missing/invalid sensor requests full cooling and logs the issue.
The Linux reader selects cpu-thermal or bcm2835_thermal and converts millidegrees.

MachineService remains the only controller authority. The worker uses the
already initialized shared Ender owner, requires E3 mainboard V1 identity,
checks M123 commanded state, and can send only M106 P1 S0 or S255. It never
opens another serial port, resets/reconnects, homes, moves, arms, writes settings,
or changes FAN2. It may update FAN1 during a primary job without sending M5 to
the primary controller. Busy exchanges and active probing defer cooling updates.
All output readbacks are commanded state, not electrical/RPM feedback.

STOP or a cooling error latches cooling paused until explicit Ender owner
reinitialization. It cannot automatically restore fan power after a stop.
Manual FAN1 ON is rejected while automatic cooling owns it; manual OFF is
accepted and pauses automatic cooling until reinitialization. Existing disarm,
job and disconnect cleanup still attempt their fan OFF commands; if a cleanup
does not stop/invalidate the controller session, a later temperature tick may
restore cooling. Service shutdown cancels the worker before controller cleanup.
An unavailable Ender or stopped service cannot provide this cooling.

The Pi-only kit generated by scripts/package_cpu_cooling.py validates all old
source hashes before updating remote_node.py and machine/service.py and adding
two cooling modules. Existing z_probe.py and secondary_startup.py patches are
preserved. It requires the service inactive, backs up replaced files, and
atomically replaces each file while retaining existing line endings. If an
installation is interrupted, keep the service stopped and rerun the installer;
known already-installed files are accepted. Unknown local edits are preserved.

Install the generated kit with its install_cpu_cooling.py --project PROJECT
--apply. Install the included 45-e3-cpu-cooling.conf as a systemd service drop-in,
run daemon-reload, and start e3-hardware-node.service. Read journal messages
containing 'CPU cooling' and compare the logged temperature/demand to actual
fan operation. No firmware update or motor movement is part of installation.
To disable, remove only this drop-in and restart the service after daemon-reload.

Validation: focused Windows tests cover thresholds, invalid sensors, shared
controller commands, FAN2 preservation, stop/session races, manual ownership,
worker shutdown and installer integrity. Linux sensor/service behavior is mocked
in these tests. The fast CI Linux job also includes the cooling tests. Automatic
45/40 C switching is not physically qualified until an operator records it.

# Next Z calibration checks

The installed compact firmware with host endpoint fix 393a2d2c has operator
observations for native homing, final Z20 clearance and Z21/back-to-Z20 movement.
A roughly 7 mm piece reported 6.984, 6.983 and 6.984 mm in one unchanged session,
using a -0.001 mm border contact and configured 1.5 mm border-to-honeycomb offset.
The 0.001 mm reported range is not a claim of micron-level physical accuracy.

1. Independently measure actual Z travel for a commanded 5 mm move (Z20 to Z25
   and back) using a dial indicator or securely positioned caliper. Remain within
   the existing five-millimetre per-move guard. Compare both approach directions;
   do not adjust the current 400 steps/mm solely from nominal material thickness.
2. Measure several sample pieces independently, such as approximately 2, 7 and
   10 mm, then probe them at the same bed location using one border reference.
   Constant error suggests checking the support offset; error growing with
   height warrants checking travel scale. Neither pattern alone proves a cause.
3. Repeat a known sample at several honeycomb positions to distinguish local
   support variation from travel-scale or reference errors. Reposition through
   the primary controller's normal E3 jog path, preserving the Ender Z reference.

Keep laser emission disabled during these mechanical tests. The current
reference-border command still requires one subsequent measure-height at the
border to complete its measurement baseline. Combining those operations into
one reference command remains a workflow improvement to implement separately.
